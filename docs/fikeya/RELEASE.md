# Fikeya release process

Fikeya `0.1.0-beta.1` is distributed as a GitHub prerelease with verifiable component artifacts:

- the Windows x64 user installer;
- the focused Windows x64 VS Code extension;
- Python wheels and source distributions for Agent Core, Runtime, and Interop;
- `release-verification.json` with size, SHA-256, Git commit, and Authenticode status;
- `SHA256SUMS.txt` for independent download verification;
- GitHub artifact provenance generated by the release workflow.

## Build locally

Run from a reviewed Windows checkout:

```powershell
./scripts/fikeya/package-release.ps1
```

The script only clears `release-artifacts` inside the repository. It builds Python distributions, the isolated VSIX, and a fresh Desktop package before creating the installer. It never reuses a stale packaged application. The output manifest records whether the executable has a valid Authenticode signature.

## Trusted Windows publisher

Setting `AppPublisher` changes installer metadata but does not establish publisher trust. Windows displays a verified publisher only when the final executable carries a valid Authenticode signature chained to a trusted certificate.

The release workflow signs when both repository secrets exist:

- `FIKEYA_SIGNING_PFX_BASE64`
- `FIKEYA_SIGNING_PFX_PASSWORD`

The signing certificate must belong to the actual publishing person or legal entity. Never commit the certificate or its password. After signing, the workflow verifies `Get-AuthenticodeSignature` before publishing the manifest and hashes.

## Release gate

Before promoting a beta to stable:

1. all Fikeya component checks pass on Windows, macOS, and Linux;
2. the Windows installer reports `Valid` Authenticode status;
3. clean-install, launch, update, and uninstall checks pass;
4. the VSIX installs into a clean supported VS Code profile;
5. wheels install into a clean Python environment and `fikeya doctor` passes;
6. every uploaded artifact matches `SHA256SUMS.txt` and its provenance record.
