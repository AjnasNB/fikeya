Real Desktop control boundary

Draft, review, and approval remain visibly different states.

These captures come from a disposable project running inside the real Fikeya Desktop extension host. They show one durable three-step plan progressing to its first exact approval boundary.

01 / Draft

The proposal is inspectable before it becomes executable.

Fikeya shows the ordered steps, dependencies, exact tool names, arguments, and expected checks. Every step remains pending.

02 / Review

Review changes plan state, not tool authority.

The reviewed revision stays visible with its same steps and arguments. The developer can start the approval phase or cancel the plan.

03 / Approval

The exact first request is exposed before execution.

Fikeya identifies the selected tool, dependencies, arguments, and expected verification while the step remains Awaiting Approval.

Capture boundary: this sequence demonstrates state separation and the pre-execution control surface. It is not an execution-result or model-quality benchmark.
