01Quickstart

From a clean folder to Chat.

  1. Install one surface.

    Use the Windows Desktop installer, the focused VSIX in a supported VS Code host, or the CLI bundle.

  2. Open a trusted local folder.

    Fikeya validates the workspace root before any context or tool request is allowed.

  3. Initialize the workspace.

    Run Fikeya: Initialize Workspace from the Command Palette, then Fikeya: Run Doctor. The CLI equivalents are shown below.

  4. Configure a provider.

    Use the compact Add model dialog for a hosted API, cloud endpoint, routed model, Ollama, or another local compatible server. Secret bytes go to the operating-system vault, not project files.

  5. Open Chat.

    Use Ctrl+Alt+I on Windows and Linux or Cmd+Alt+I on macOS. The Fikeya Desktop opens Project Chat by default; the focused extension opens Chat beside the existing editor.

  6. Inspect before running.

    Open Plan to review stages and Context to inspect cited evidence. Approve each risky tool request only when it appears.

fikeya init . --json
fikeya doctor . --json
fikeya provider list --json
02Providers

Bring your API key, workload identity, or local model.

Supported paths include OpenAI API models, Azure OpenAI, Azure AI Foundry compatible endpoints, Anthropic, Gemini, Vertex AI, Hugging Face Inference Providers, Groq, OpenRouter, NVIDIA NIM, DeepSeek, Mistral, xAI, Together, Fireworks, Cerebras, Amazon Bedrock, Ollama, local no-auth servers, and custom OpenAI-compatible endpoints. Availability still depends on your provider account and selected model.

Subscription boundary

A ChatGPT, Codex, Claude, Gemini, or other consumer subscription is not reused as API access. Configure the provider credential or supported workload identity separately.

Configure Azure OpenAI with Entra ID

fikeya provider configure work \
  --kind azure-openai \
  --base-url https://YOUR-RESOURCE.openai.azure.com \
  --model YOUR-DEPLOYMENT \
  --credential-type entra-id \
  --api-mode responses

Configure Gemini with an API key

fikeya provider configure work \
  --kind google-gemini \
  --model gemini-2.5-pro \
  --credential-type api-key

The interactive prompt accepts the secret without adding it to the command line. Automated callers may pass --secret-stdin and stream it once over standard input.

Test a configured route

fikeya provider test work --allow-network --json
03Chat and Plan

Keep the conversation beside the work.

The primary Fikeya destinations are Chat, Plan, Context, and Usage. Native editor, terminal, source control, review, and settings remain native workbench surfaces.

When Qarinah context is enabled and available, Chat recompiles bounded project evidence for each turn. Risky tools still require exact approval, and terminal runs attach their resulting local receipts.

Read the timeline correctly

  • Draft means Fikeya has a proposed sequence, not permission to run.
  • Review exposes provider, workspace, context, objectives, and dependencies.
  • Approval means a human accepted the plan boundary. Exact risky calls still require one-use permission.
  • Execute shows current step and tool state.
  • Verify binds checks and outcome hashes to the completed work.
04Qarinah Context

See what the task received and where it came from.

Context shows a bounded graph of files, symbols, decisions, worktrees, conflicts, references, tools, and outcomes. Select a node to inspect its source identity and evidence hash. Use the full-graph action when the editor group is narrow.

A stale or unavailable index stays unavailable. Fikeya does not replace it with sample data.

Privacy boundary

Qarinah keeps durable project evidence. It excludes provider secrets, hidden model reasoning, and unrestricted tool output. Content capture remains an explicit workspace policy.

05CLI

Automate through the same runtime contract.

Read prompts from standard input so they do not enter process arguments. Network access remains an explicit opt-in, and agent-requested tools still pause for exact approval.

Get-Content .\task.txt | fikeya agent execute . \
  --provider work \
  --prompt-stdin \
  --allow-network \
  --memory required \
  --json

Use fikeya stats --workspace . --json for content-free local session, call, usage, and context-receipt aggregates. Missing provider token measurements remain unavailable.

Current boundary

07Troubleshooting

Keep failure states specific.

Chat does not show a model
Open Fikeya Settings, configure at least one provider profile, then refresh profiles.
Context says unavailable
Run workspace initialization and Doctor. Rebuild a stale Qarinah index before using its graph as evidence.
A tool does not run
Check the executable allowlist, workspace root, network setting, exact approval, and expiry. A changed argument invalidates the grant.
Token counts are unavailable
The provider did not report them or no call has completed. Fikeya does not invent provider billing.
Windows says unknown publisher
The current beta is not Authenticode-signed. Verify the published SHA-256 checksum. A trusted-publisher label requires a real signing certificate or Azure Artifact Signing.
