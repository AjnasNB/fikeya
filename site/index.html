One editor. Four ways to work.

Switch the surface without moving the project. Code OSS supplies the mature editor, terminal, debugger, Git, language services, and extension host. Fikeya adds the model runtime, receipts, and project intelligence around them.

01

Editor Mode

Navigate, refactor, debug, search, and write inside a complete Code OSS workbench. Provider and context status stay visible without replacing the editor.

  • Monaco and language servers
  • Git and merge tools
  • Debugger, tasks, and extensions
02

Agent Mode

Run a bounded provider turn, choose the model, set output limits, cancel work, and inspect exact receipts. The checkpointed plan and approval core is shipping as a tested component while desktop wiring continues.

  • Provider-neutral execution
  • Cancellable network calls
  • Durable usage receipts
03

Terminal Mode

Use the full integrated shell directly. Automated commands remain behind the separate execution broker and exact approval contract until that path is connected to the desktop.

  • Persistent integrated shells
  • Tasks and process output
  • Root-bound broker contract
04

Review Mode

Move from the model answer to the evidence: provider usage, request and response digests, project graph identities, Git changes, and test output.

  • Source control review
  • Provider and evidence receipts
  • Verification status

Context selected, not dumped.

Optimization that has to prove itself.

Fikeya's engineering target is lower cost per verified successful task, not a smaller prompt that causes more retries. The matched benchmark harness pins the model, provider, repository, tools, limits, and tests before comparing runs.

Internal target: at least 50% fewer billed input tokens with no material solve-rate regression. This is a target, not a released performance claim.
