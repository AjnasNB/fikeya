Desktop workbench

Everything needed to plan, build, run, and review.

Fikeya Desktop includes the complete editor, terminal, debugger, Git, language services, and extension host. The companion editor extension stays intentionally smaller: one Agent workspace for providers, Qarinah memory, approvals, receipts, and local usage statistics.

01

Editor Mode

Navigate, refactor, debug, search, and write inside the complete Fikeya workbench. Provider and context status stay visible without replacing the editor.

02

Agent Mode

Run the tested plan-act-observe-review loop, choose the model, set limits, approve each exact tool request, cancel work, and inspect provider and execution receipts.

03

Terminal Mode

Use the full integrated shell directly. Agent-requested processes run through the root-bound broker and require an exact one-use approval before execution.

04

Review Mode

Move from the model answer to the evidence: provider usage, request and response digests, project graph identities, Git changes, and test output.

05

Lab Mode

Compare configured models on the same bounded task, inspect usage and verification receipts, and keep experiments separate from normal coding work.

Bring your own key or local model

Use the model that fits the job.

Fikeya keeps provider metadata inspectable and credential bytes in the operating-system keyring. Use OpenAI API models, including Codex-capable models available to your API account, Azure OpenAI, Anthropic, Gemini, Vertex AI, Hugging Face Inference Providers, Groq, OpenRouter, NVIDIA NIM, Ollama, or another OpenAI-compatible endpoint.

Bring your own API credential or local model. Fikeya does not reuse a ChatGPT, Codex, Claude, Gemini, or other consumer subscription as API access. Vertex uses a short-lived Google Cloud token today; automatic ADC refresh is a release follow-up.

You choose the exact profile and model. If a provider returns a quota or rate-limit response, Fikeya can ask to continue with another configured model or remember an "always switch" preference while recompiling the same task-relevant Qarinah context.

Qarinah project intelligence

Retrieve the evidence this task needs.

Qarinah is the local context engine under Fikeya. It retrieves task-specific, evidence-linked project records within a bounded budget. The graph remains searchable and inspectable so the developer can see what exists and where it came from.

Optimization that has to prove itself.

Fikeya's engineering target is lower cost per verified successful task, not a smaller prompt that causes more retries. The matched benchmark harness pins the model, provider, repository, tools, limits, and tests before comparing runs.

Internal target: at least 50% fewer billed input tokens with no material solve-rate regression. This is a target, not a released performance claim.
