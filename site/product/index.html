Plan to proof

Five states separate an idea from verified work.

Chat and cited Qarinah context prepare the task. The durable workflow then moves through Draft, Review, Approval, Execute, and Verify. A reviewed plan is not permission to run, and an approval is not proof that execution succeeded.

  1. 01Draft

    Turn the request and cited context into ordered steps, exact tools, dependencies, and expected checks.

  2. 02Review

    Inspect the immutable revision and request changes before any tool can run.

  3. 03Approval

    Grant a short-lived, single-use approval for one exact tool call and its arguments.

  4. 04Execute

    Run only dependency-ready approved work while recording state and changed files.

  5. 05Verify

    Bind declared checks, exit state, output hashes, and affected-file hashes to the step.

In the real Desktop sequence on the Proof page, three read-only workspace tools reached Succeeded after three separate exact approvals. The receipt links every tool call to its result, execution, and verification hashes without mutating project files.
